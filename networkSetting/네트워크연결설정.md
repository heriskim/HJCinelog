## 네트워크 연결 설정

### 배경
사내(기업) 네트워크 환경에서는 SSL 검사(프록시)가 걸려 있어, Node.js 프로세스가 외부 HTTPS API(TMDB, Supabase 등)를 호출할 때 사내 프록시가 발급한 인증서를 신뢰하지 못해 TLS 오류가 발생할 수 있다. 이를 해결하기 위해 사내 루트 CA 인증서 묶음을 `certs/windows-ca-bundle.pem`에 두고, Node.js 실행 시 `NODE_EXTRA_CA_CERTS` 환경변수로 지정한다.

### 현재 설정
- 인증서 파일 위치: `certs/windows-ca-bundle.pem`
- 적용 방식: `package.json`의 `dev` / `build` / `start` 스크립트에서 `cross-env NODE_EXTRA_CA_CERTS=./certs/windows-ca-bundle.pem`으로 지정
- 적용 범위: 해당 스크립트로 실행되는 Node.js 프로세스의 모든 아웃바운드 HTTPS 요청(TMDB API, Supabase API/Storage 포함)에 동일하게 적용됨

### 유지 규칙
1. `npm run dev` / `npm run build` / `npm run start` 이외의 방식(예: `next dev`를 직접 실행)으로 서버를 띄우면 이 환경변수가 빠질 수 있으니, 반드시 npm 스크립트를 통해 실행한다.
2. 인증서가 만료되거나 사내 프록시 인증서가 교체되면 `certs/windows-ca-bundle.pem`을 최신 버전으로 교체해야 한다.
3. 새로운 외부 API(TMDB, Supabase 외)를 연동하거나, 사내 프록시/네트워크 정책이 변경되는 경우 이 문서를 먼저 확인하고, 필요 시 위 설정 방식(스크립트에 `NODE_EXTRA_CA_CERTS` 지정)을 그대로 따른다.
4. 이 문서 자체가 변경되면 CLAUDE.md의 참조 링크가 최신 상태인지 함께 확인한다.

### 문제가 재발할 때 확인 순서
1. 서버를 `npm run dev`(또는 build/start)로 실행했는지 확인
2. `certs/windows-ca-bundle.pem` 파일이 존재하고 최신인지 확인
3. 서버 로그에 `UNABLE_TO_VERIFY_LEAF_SIGNATURE`, `self signed certificate` 등 TLS 관련 에러가 있는지 확인
4. 브라우저 쪽 "네트워크 오류"는 클라이언트 fetch 자체가 실패한 경우이므로, 서버 로그에 에러가 없다면 TLS/인증서 문제가 아니라 다른 원인(요청 크기, 세션 만료 등)일 가능성이 높다
